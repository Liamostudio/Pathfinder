# Pathfinder demo: a live-updating safety system for robots (4 Nov)

Pathfinder watches a robot's workspace, keeps a live 3D map of where the robot may and may not go, updates it from live cameras, and lets a person
instruct the robot in plain language from their own point of view. Models propose and describe; a small, checkable safety layer decides. A model never
drives a motor.

## The five beats, with the models behind each

| # | Beat | Models | Where it runs | State today |
| --- | --- | --- | --- | --- |
| 1 | Ingest photos or video of the workspace; build a layered 3D map | **MapAnything** (Meta) for geometry and cameras; **SAM 3.1** (Meta) for table, wall and robot masks; Gaussian fit for appearance | Legion GPU, local, no API | Built and demonstrated by Codex (`set up workspace`); reconstruction quality not independently tested |
| 2 | Voxel overlay; draw manual no-go areas | none (geometry) | local | Voxel editor built. **No-go cubes are now enforced as hard rules for the arm** (`lookandpick/zones.py`): a move whose path crosses one is refused before the arm is commanded, and the model is told why (tested with real grids; sim arm only) |
| 3 | Live cameras update the map in real time | **Fast, safety (every frame, about 28 fps, CPU): MediaPipe Hand Landmarker** (Google). **Slow, rich (about 1 per second, GPU): SAM 3.1** (Meta), prompts "person" and "hand", marks the voxel map. Codex's browser path also uses EfficientDet-Lite0 (Google) for person boxes | Legion | Hand gate and voxel feed built and tested; hand gate seen working on a real hand (32 s). SAM 3.1 people feed built and tested with fakes; **not yet seen on a real person**. Voxel feed **not yet seen with the live camera** (Ace Pro was unplugged after a restart) |
| 4 | Meta glasses: natural-language prompts from the user's view | **Muse Voice Transcribe** (Meta) for speech; **Muse Spark** (Meta) sees the glasses photo plus the scene and resolves "this one" | Meta Model API | Built and tested with fakes; live with a sim frame standing in for the glasses view ($0.007). **Real glasses not connected** (see below) |
| 5 | Intuitive, safe interaction | the same five validated tools, the stop latch, the hand gate | local | Built |

Everything that decides whether the arm moves is local and needs no network: the hand gate (150 ms watchdog, latched stop), the no-go cubes, the stop word.

### Why two detectors in step 3, and what is Meta's

The live loop has a hard deadline: a hand has to slow the arm within a fraction of a second. SAM 3.1 answers in 0.6 to 1.0 s on this laptop's GPU, which is too slow
to be the safety path, so MediaPipe (28 fps) is. SAM 3.1 is the slower, richer layer: it segments whole people and hands (not just landmarks) and paints the map.
That is the honest split to describe: **fast and simple enforces, slow and rich explains**. Do not claim SAM 3.1 is in the safety loop.

An RGB camera cannot certify that space is empty. Camera detections can only turn cubes red; **no cube ever turns green from a camera**, and unknown cubes count as unsafe in the map.

## Run of show

```bash
# 0. services
python3 simulation/start.py                                                    # the simulated arm (127.0.0.1:8766)
PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True ~/src/sam3-venv/bin/python scripts/sam_worker.py   # SAM 3.1 worker (holds the GPU; stop it before reconstruction)
# 1. Deck with the live camera, live hands and SAM people in the voxel map, no-go cubes enforced
PYTHONPATH=. ~/src/hands-venv/bin/python -m lookandpick.mission_control --backend sim --model spark \
    --hand-gate 2 --intrinsics calibration/ace-pro.json --sam-people \
    --second-camera N --second-intrinsics calibration/<second>.json            # optional second camera on the same gate (each needs its own lens file)
# 2. glasses-style command from the terminal (photo + spoken or typed request)
.venv/bin/python -m lookandpick.runtime --scene sam --view glasses_view.jpg --audio request.wav
```

## Two cameras
`--second-camera` puts a second camera behind the SAME gate: each camera projects hands into the shared marker frame and the newest hands from both are combined
into one observation for the one watchdog. A hand seen by either camera slows the arm; if either camera stalls, the arm stops (fail safe). Both cameras must see the
marker (it ties them to the same coordinates) and each needs its own lens calibration (`scripts/calibrate_lens.py --name <camera>`). Put the second camera on a different USB
port from the first, ideally USB 3, so they do not share one USB 2 connection.

**Tests and the GPU lease:** the SAM worker holds the shared GPU lease while it runs, so stop it before `scripts/test_all.sh` or a reconstruction.
